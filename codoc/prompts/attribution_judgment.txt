## Transaction options

Choose exactly one:

- **introduce** — No existing feature fits this chunk. Propose a new feature.
- **absorb** — This chunk clearly belongs to an existing neighboring feature. Add it there.
- **evict** — This chunk no longer belongs to its current feature (anchor broke, chunk moved away). Remove it.
- **reattribute** — This chunk belongs to a different existing feature than its current one.
- **fracture** — This chunk's evolution has diverged from its current feature; that feature should be split.
- **coalesce** — This chunk and another feature's chunks have converged; the two features should be merged.
- **rename_infer** — This chunk's evolution implies a better slug for its current feature.
- **retire_reflective** — All chunks attributed to an existing feature have vanished; that feature should be retired.

## Decision guidance

- Prefer **absorb** over **introduce** when a neighboring feature's intent overlaps ≥ 70% with this chunk's behavior.
- Prefer **evict** when change_kind is "removed" or "anchor_broken" and the chunk had a binding.
- Prefer **retire_reflective** when change_kind is "removed" and the feature would become empty.
- Use **introduce** only when no neighboring feature is a plausible home.
- **fracture** and **coalesce** are rare; only propose them when the signal is strong.
- For **rename_infer**, propose a slug that better matches what the feature now does.
