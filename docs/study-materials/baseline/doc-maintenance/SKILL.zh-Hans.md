# 维护 CLAUDE.md

CLAUDE.md 是团队对本代码库的功能级说明：每个章节命名一个功能，说明它的用途、为什么要这样构建，以及哪些代码承载它（`file.py::symbol` 引用）。团队将它视为意图的事实来源。你的工作是在每次修改后让它保持为真。

## 在每次代码变更之后，在你认为任务完成之前

1. **更新受影响的章节。** 对于你触及其代码的每个章节：重新阅读它，并重写任何因这次修改而变得不再正确的内容。只要作者的措辞仍然正确，就保留它——修复，不要重写。
2. **记录原因。** 当你的修改体现了一个决策（选择了一层、做出了权衡、拒绝了某个替代方案）时，在该章节里写一句理由：做了什么决定、为什么，以及如果你考虑过替代方案就说明拒绝了什么。用户明确提出的要求就是理由——引用它们。
3. **保持代码引用最新。** 对于你移动、重命名、添加或删除的代码，更新 `file.py::symbol` 引用。指向一个不再存在的符号的引用，就是你引入的 bug。
4. **声明新代码。** 如果你添加了某个没有任何章节描述的代码，要么扩展最合适的章节，要么新增一个章节（标题 + 1–3 句描述 + 引用）。绝不要让新的行为无人描述。
5. **标记你无法验证的内容。** 如果一项修改可能让其他章节过时（合同变更、职责迁移），检查它们；如果你不能确定，就在该章节上方加上 `> STALE?`，并用一行说明原因。

## 规则

- 描述要说明代码为系统做了什么，以及为什么——不是逐行叙述，也不是变更日志。每个功能一段话。
- 除非修改真的使其失效，否则绝不要删除章节里记录的理由（“why / rejected alternative”）——如果失效了，就用新的理由替换。
- 如果用户在聊天中做出决定（范围、行为、命名），把它记录到相关章节里——只存在于对话中的决定会在会话结束后丢失。
- 在代码变更的同一个回合里完成所有这些。不要留到以后批量处理；也不要询问是否可以更新文档。
