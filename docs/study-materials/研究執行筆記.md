# codoc 研究執行筆記

給主持人（experimenter）看的一頁式流程。英文完整版在 `experimenter-guide.md`，
這份只寫「要做什麼、在哪裡做」。

---

## 一、這個研究在比什麼

每位受試者做兩次任務，一次用 codoc，一次不用，兩次都用 Claude Code。
兩次都有一份「寫下來的說明」（written description），也都被要求保持它是最新的。
差別只有一個：那份說明怎麼維護。

| | 有 codoc | 沒有 codoc（baseline） |
| --- | --- | --- |
| 說明放在哪 | codoc 的 feature tree，綁定到程式碼 | `CLAUDE.md` |
| 誰更新它 | codoc 提出修改，受試者按 Accept / Reject | agent 被要求每次改完就自己更新 |

兩個專案：**hearth**（靜態網站產生器）和 **ember**（RSS 摘要工具）。
一人一個專案配一種做法，所以沒有人會做到同一個題目兩次。

---

## 二、你需要準備的三樣東西

1. **`dist/codoc-study-bundle.zip`** — 從 repo 根目錄執行
   `./docs/study-materials/scripts/build-participant-bundle.sh` 產生。
   裡面有 extension、四個專案、安裝腳本。codoc 有更新就重新產生一次。

2. **兩把 API key**（研究經費付，受試者不用花錢，也不需要 Claude 訂閱）
   - Anthropic key → 跑 Claude Code，`claude-sonnet-5`，thinking 設 medium
   - OpenAI key → 跑 codoc，`gpt-5.6-luna`

   **請用專門為這個研究開的 key，設好 spend limit，研究結束就停用。**
   key 一旦到了別人電腦上就收不回來，額度上限和停用是你唯一的保護。

3. **兩個網頁**
   - 你的後台：<https://codoc-11b10.web.app/experimenter/>（用 MIT 帳號登入）
   - 受試者頁面：只能透過你發的連結進入

## 三、招募與排程（做完 14 位）

後台的名單就是計畫本身：**2 位 pilot + 12 位正式受試者**，
還沒建立的位置也會顯示出來，所以你隨時看得到還缺幾位、缺哪一種順序。

- 順序（order）由系統決定，兩種交替，不用自己記。
- 中途停招也沒關係，交替排法留下來的一半仍然是平衡的。
- **先跑完 2 位 pilot 再跑正式的。** pilot 是用來發現流程有問題的，
  所以預設不會進入分析。

---

## 四、事前（至少提前三天）

1. 後台按 **New**，得到一組 code（例如 `p-abcdefghjkmn`）。
2. 頁面最上方那張卡有三樣要交給受試者：
   - **他的連結**（已含 code 和 order）
   - **他要執行的指令**，例如 `./setup.sh p-abcdefghjkmn codoc-first`
   - **兩把 key** — 這個要你自己給（口頭念、或另外傳一個 `keys.env`）。
     **key 不會經過網頁，也不在 zip 裡**，zip 只做一次卻要發給所有人。
3. 把 zip 寄給他，請他打開連結一路做到頁面叫他停為止
   （包含同意書 consent、背景問卷、安裝）。
4. 回來看那張卡上的**兩個圓點**：
   - 第一個變綠 = 他打開連結了
   - 第二個變綠 = 他的編輯器有回報了（代表 setup 有跑成功、code 有設對）
   - 第二個沒綠 = 他做的任何事都不會傳到你這裡。請他跑 `./setup.sh --check`。
5. 請他把 setup 最後幾行貼給你。沒看到「Everything is ready」就先解決。

> 排除條件：背景問卷裡問「agent 改好幾個檔案時你會不會先看 diff」，
> 回答「從不」的人不要跑。後台看得到這題。

## 五、當天流程（約 105 分鐘）

| 順序 | 做什麼 | 在哪裡 |
| --- | --- | --- |
| 1 | 請他跑 `./setup.sh --check`，念結果給你聽 | 他的終端機 |
| 2 | 開始**分享整個螢幕**並錄影 | Zoom |
| 3 | 他照著自己的頁面走：怎麼開專案、專案介紹、任務卡 | 受試者頁面 |
| 4 | 他做任務，你在旁邊看，請他 think aloud | — |
| 5 | 他做完，填該次的問卷 | 受試者頁面 |
| 6 | 休息幾分鐘，換另一種做法、另一個專案，重複 3–5 | — |
| 7 | 最後填「哪種情況你會選哪個」和兩題開放問答 | 受試者頁面 |
| 8 | 請他跑 `./collect.sh <他的 code>`，把產生的檔案傳給你 | 他的終端機 |

**你在後台同時要做的**（打開他那一頁，就在通話旁邊）：
- 每次任務結束記 **sign-off**（他覺得對不對、多有信心、信心從哪來）
- 記 **哪些決定是誰做的**（who settled what）
- 問完十題理解問題後，就地打分（每題都有評分表在旁邊）

> 專案介紹和啟動步驟都寫在受試者頁面上，你不用口頭講。
> 這是刻意的：那段差異本身就是實驗操弄，臨場講會每個人講得不一樣。

## 六、如果卡住

| 狀況 | 怎麼辦 |
| --- | --- |
| 他換電腦、重裝，編輯器說「請主持人 release」 | 後台那張卡上按 **release this code** |
| 第二個圓點一直不綠 | 請他跑 `./setup.sh --check`，看有沒有印出 code |
| setup 說 key 被拒絕 | key 失效或額度用完，換一把新的給他 |
| `claude` 找不到 | 裝完要重開終端機（PATH 才會更新） |

---

## 七、資料在哪裡

| 東西 | 從哪來 |
| --- | --- |
| 操作記錄（interaction log） | study logger extension，兩種做法都裝，即時傳到後台 |
| 對 agent 說的話 | Claude Code 的 transcript，事後用 `collect.sh` 收 |
| 專案每 20 秒的快照 | `session-log.sh`，可以逐步重播 |
| 問卷答案 | 受試者頁面，直接進資料庫 |
| 你的評分和筆記 | 後台，邊做邊存 |
| 同意書、年齡性別 | 留在 Google 表單，**不會進研究資料庫** |

事後把一位受試者的資料抓下來：
```
node study-app/scripts/export-session.mjs <他的 code> --out <資料夾>
python3 docs/study-materials/scoring/check-session-complete.py <資料夾>
```
第二個指令會直接告訴你少了什麼。

## 八、看結果

後台左上角按 **Results**，四張圖會用目前收到的全部資料重畫：

1. **問卷結果** — 兩種做法的作答分佈，右邊第三欄是配對後的平均差和 95% 信賴區間
2. **時間都花在哪** — 每次 session 拉到同一條時間軸上，看注意力怎麼移動
3. **說明是誰寫的** — 這張最重要。論文主張說明是「共享的」，
   這張圖也能顯示主張不成立的兩種樣子：只有 agent 在寫，或只有人在寫
4. **哪個動作接在哪個後面** — 說明到底有沒有在流程裡，還是只是被放在旁邊

每張圖都可以匯出 **SVG / PNG / CSV**，SVG 可以直接放進論文。
**pilot 預設不計入**，要看的話自己勾。
